# ドキュメントの記載方針

## README

- READMEは利用者向けの説明に絞り、目的・使い方・設定方法・仕様・対応範囲・既知の制約を書く。
- 未実施・未検証・確認待ちなどの一時的な作業状況、個別のテスト結果、レビュー回数・指摘件数、対応履歴は書かず、PR本文や作業報告に残す。
- 製品の仕様・対応範囲・既知の制約は、利用者が知る必要のある内容を書く。詳しい経緯はIssueやPRへ分ける。

「実デプロイ未検証」は一時的な検証状況なのでREADMEには書かず、PR本文や作業報告に残す。
「SSR 未対応」「初期状態ではデプロイ無効」は製品の対応範囲や仕様なのでREADMEに記載してよい。

テストの実行方法は使い方として記載してよいが、「テスト58件成功」「レビュー3回終了」
といった個別作業の結果は記載しない。
